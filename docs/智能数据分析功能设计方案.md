# 智能数据分析功能设计方案

## 1. 功能概述

在现有知识库问答系统基础上，新增"智能数据分析"功能。用户通过自然语言提问，系统调用大模型（qwen3:4b）将问题转换为 SQL，在 MySQL 数据库上执行查询，并由大模型根据结果推荐 ECharts 图表类型和配置，最终在前端渲染为可视化图表。

## 3. 核心流程

### 3.1 NL2SQL 流程

```
1. DBManager.get_schema() 获取数据库元数据
   → 查询 information_schema.TABLES + information_schema.COLUMNS
   → 缓存结果：{table_name: [{column, type, comment}, ...]}

2. DataAnalyzer._build_nl2sql_prompt(question, schema)
   → 组装 prompt：
     "你是一个 SQL 专家。根据以下数据库表结构，将用户问题转换为 MySQL SQL 查询。
      只返回纯 SQL 语句，不要解释。
      表结构：
      {schema_description}
      用户问题：{question}"

3. ChatOllama.invoke(prompt) → 获取 LLM 输出

4. 从 LLM 输出中提取 SQL 语句（去除 markdown 代码块标记）
```

### 3.2 SQL 安全校验

```python
import sqlparse

def _validate_sql(self, sql: str) -> bool:
    """仅允许 SELECT 语句"""
    parsed = sqlparse.parse(sql)
    for stmt in parsed:
        stmt_type = stmt.get_type()
        if stmt_type != "SELECT":
            return False
    # 二次检查：拒绝包含危险关键词的 SQL
    dangerous = ["INSERT", "UPDATE", "DELETE", "DROP", "ALTER",
                 "TRUNCATE", "CREATE", "GRANT", "REVOKE"]
    sql_upper = sql.upper()
    for kw in dangerous:
        if kw in sql_upper:
            return False
    return True
```

### 3.3 图表推荐流程

```
1. DataAnalyzer._build_chart_prompt(question, sql, columns, sample_rows)
   → 组装 prompt：
     "你是一个数据可视化专家。根据以下查询结果，推荐最合适的 ECharts 图表类型。
      返回 JSON 格式：
      {
        "chart_type": "bar|line|pie|none",
        "option": { ECharts option 配置 }
      }
      查询问题：{question}
      SQL：{sql}
      列名：{columns}
      数据（前5行示例）：{sample_rows}
      完整数据：{all_rows}"

2. ChatOllama.invoke(prompt) → 获取 JSON 输出

3. 解析 JSON，提取 chart_type 和 option
   → chart_type == "none" 时不渲染图表，仅展示表格
```

### 4.2 db_manager.py（新建）

| 方法 | 功能 | 返回 |
|------|------|------|
| `connect()` | 连接 MySQL | 连接对象/异常 |
| `get_schema()` | 获取表结构元数据 | `{table: [{column, type, comment}]}` |
| `execute_query(sql)` | 执行 SELECT 查询 | `{"columns": [], "rows": []}` |
| `test_connection()` | 测试连接是否可用 | `bool` |

**关键实现：**
- `get_schema()` 查询 `information_schema.COLUMNS`，按 table_name 分组缓存
- `execute_query()` 使用 `pymysql.cursor.DictCursor`，自动添加 `LIMIT` 保护
- 连接失败不抛异常，返回 `None`，由上层处理

### 4.3 data_analyzer.py（新建）

| 方法 | 功能 |
|------|------|
| `generate_sql(question)` | NL → SQL |
| `_validate_sql(sql)` | 安全校验 |
| `recommend_chart(question, sql, result)` | 图表推荐 |
| `analyze(question)` | 主入口，串联全流程 |

**`analyze()` 返回结构：**

```json
{

      "yAxis": {"type": "value"},
      "series": [{"type": "bar", "data": [25, 30, ...]}]

    "columns": ["department", "count"],

## 6. 图表推荐 Prompt 设计

```

## 7. 安全策略

| 层级 | 措施 |
|------|------|
| SQL 校验 | `sqlparse` 解析语句类型，仅允许 SELECT |
| 关键词黑名单 | INSERT/UPDATE/DELETE/DROP/ALTER/TRUNCATE/CREATE/GRANT/REVOKE |
| 行数限制 | 自动追加 `LIMIT 1000`，防止大结果集 OOM |
| 超时控制 | 查询超时 30 秒自动终止 |
| 连接隔离 | 使用专用只读账号（建议配置 MySQL 只读用户） |
| 异常处理 | MySQL 不可用时不影响知识库问答功能 |

## 10. 错误处理

| 场景 | 处理 |
|------|------|
| MySQL 连接失败 | 数据分析 Tab 显示"数据库未连接"，知识库问答正常 |
| LLM 生成非法 SQL | 返回"仅支持查询操作，请重新描述问题" |
| SQL 执行报错 | 返回 MySQL 原始错误信息 + 生成的 SQL 供调试 |
| 查询超时 | 返回"查询超时，请尝试缩小查询范围" |
| LLM 返回非 JSON | 图表区显示"图表生成失败"，数据表格正常展示 |
| 空结果集 | 图表区显示"无数据"，表格显示空表头 |
